# PR #170 Migration Snapshot Verification

## Purpose

The PR #170 migration moved fundamental system and electronic properties from
manual `archive.run` population to declarative `archive.data` mappings. This
harness guards the invariant that the migration is **additive**: parser output
may gain properties or change a value's representation, but it must never *lose*
archive data relative to the pre-migration baseline.

## How it works

The check is a manually triggered CI job (`.github/workflows/snapshot-tests.yml`,
`workflow_dispatch`). Snapshots are treated as generated artifacts and are **not
tracked** in the repository (`tests/parsers/__snapshots__/` and `*.ambr` are
git-ignored). Each run produces two syrupy snapshots and compares them:

- **Baseline** — parser output at the pre-migration commit
  `1c7acd60fc18827618a30f46f42eeec5664d97a1`. It is generated by adding the
  current harness (`tests/parsers/test_migration_snapshots.py`) to a worktree of
  that commit and running it with `PYTHONPATH=<worktree>/src`, so the *old*
  parser code produces the snapshot. Because it depends only on the pinned
  commit, it is cached across runs (`actions/cache`, keyed on `BASELINE_REF`).
- **Current** — parser output on the branch under test, generated with
  `pytest --snapshot-update`.

`tests/parsers/compare_snapshots.py` then flattens both snapshots to
`path -> value` leaves, aligns lists by index, and reports per fixture the
leaves `added`, `changed`, and `removed`. The job fails if any leaf is
`removed`, i.e. if the current archive drops data the baseline had.

Deterministic section ordering is required for a stable comparison; the
nomad-lab pre-releases resolved from the MPCDF registry include that fix, so no
special handling is needed in CI.

## Result

The migration is additive. Across the parser fixtures the current output is a
structural superset of the baseline — no leaves are removed. The substantial new
data is the migrated electronic properties (eigenvalues, DOS, band gaps) and
`model_system` content (lattice vectors, positions, periodic boundary
conditions, atom states).

Two fixtures show `changed` leaves; both are representation changes of the same
physical quantity, not data loss:

- **VASP OUTCAR** — `electronic_eigenvalues` values change by the elementary
  charge (eV stored as J).
- **QuantumESPRESSO** — `model_system.positions` change from fractional to
  cartesian coordinates (a correctness fix).

An earlier revision of this report concluded the migration was "not purely
additive" with ~2,900 deleted lines. That was an artifact of comparing snapshots
with `diff -u`, which reports list reorderings and the representation changes
above as deletions. The structural per-leaf comparison used here does not, and
confirms no archive data is lost.
